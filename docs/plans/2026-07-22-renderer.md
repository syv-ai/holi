# Plan 5 — The Shell Boots

> **For agentic workers:** Use the executing-plans skill to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Render `App` instead of the instrument panel, and end with a vault one person can actually use — sign in, open a vault, browse the tree, edit a note, watch it commit and publish.

**Architecture:** The renderer consumes the seam plans 1–4 finished and adds nothing to it. One source of truth per concern: `snapshotAtom` is the vault (pushed from main, never re-queried per file), `syncStateAtom` is the indicator, `panesAtom` is what is on screen. Components stay thin; every decision worth testing lives in a `.ts` module beside them.

**Tech Stack:** React 19 + jotai + CodeMirror 6 + tRPC over the one IPC channel. Vitest in `environment: 'node'`.

**In:** session/sign-in, vault list and open, the file tree, the editor (save, flush, 3-way reload), the sync indicator, the pane/tab *shape*, the collaborators panel, and `main.tsx` rendering `App`.

Those files stay on disk, erroring, **quarantined the same way `main/agent/` is** — nothing on the boot path may import them. `Shell.tsx` is currently the only importer of all five (`AgentPanel`, `HistoryPanel`, `state/agent`, `state/history`, `state/daily`), so Task 10 stripping its imports is what puts them out of reach. `HistoryPanel.tsx` and `state/agent.ts` typecheck clean and contribute nothing to the count — they are quarantined by association, because what they import does not. That is the rule that keeps the app launchable while the type errors are still being paid down (`electron-vite` resolves imports without typechecking, so an unresolvable import is the one thing that stops a window opening).

**Acceptance:** typecheck errors go **109 → 50**, and every one of the 50 is in a quarantined file:

```
AgentPanel 20 · daily 14 · history 6 · agent-manager 7 · context-snapshot 3
```

If the number is not 50, something on the boot path is importing something it should not.

**Expect the total to go UP at times, and do not treat it as a regression.** Several of these files typecheck against imports that do not resolve, which makes the value `any` and silences every use of it. Giving one a real type exposes the callers that were riding the lie — Task 3 typed `sessionAtom` properly and immediately surfaced `session.email` and `session.userId` in `EditorPane`, fields `PublicViewer` does not have. The handoff recorded the same thing at 106 → 109. **The 50 is what matters**, because the quarantined set is the only part of the count that is not being actively paid down.

## Contracts this consumes

Finished, tested, and not to be changed by this plan.

```ts
// window.holi — renderer/src/global.d.ts
trpc(op)                       // the whole router, via lib/trpc.ts
vault.onSnapshot(cb)           // full VaultSnapshot, pushed on every change
vault.onSyncState(cb)          // SyncState, pushed on change only
vault.onFlushRequest(cb)       // main is quitting: write buffers, then ack
vault.flushDone()              // the ack. Main waits 1s, then quits regardless
openExternal(url)

// router
auth.status | signIn | awaitSignIn | cancelSignIn | signOut
github.repos | orgs | collaborators | openCollaboratorSettings | createRepo
vaults.list | add | create | open | snapshot | remove
notes.read | write | create | delete
sync.state | commitNow | publish | pause | resume

// @holi/shared
DocMeta { path, kind, updatedAt }      // NO id — the path is the identity
Task    { path, title, status, … }     // NO id, NO related[]
VaultEntry { remote, path, name, lastOpenedAt }   // NO id — the remote is the identity
merge3(base, mine, theirs) -> { kind:'merged', text } | { kind:'conflict', regions }
```

**`SyncState`** is `up-to-date | ahead{count} | pulling | publishing | offline | conflict{paths} | reconciling | paused{reason}`, and its **priority order is decided in main** (`computeState` in `active-vault.ts`, which has a comment explaining why pause outranks conflict). The renderer renders whatever arrives. It must never re-derive or re-order.

## Task 9: The editor

The largest task, and the one four handoffs have predicted a bug in.

**Files:**
- Create: `apps/desktop/src/renderer/src/lib/editor-reload.ts`, `apps/desktop/test/editor-reload.test.ts`
- Modify: `apps/desktop/src/renderer/src/components/EditorPane.tsx`

**Contract:**

```ts
type Reload =
  | { kind: 'none' }                       // disk === base: nothing happened that concerns us
  | { kind: 'reload'; text: string }       // clean buffer: take disk
  | { kind: 'merged'; text: string }       // dirty buffer, merge3 succeeded
  | { kind: 'conflict'; regions: ConflictRegion[] }

decideReload(base: string, buffer: string, disk: string): Reload
```

- [ ] **Step 1: Write the failing test — `disk === base` is a no-op whoever wrote it**

This is plan 4's decision 7, and it is the whole write-attribution design: **the editor's own save needs no attribution.** It saved, so it advanced `base`; when the watcher reports that write, `disk === base` and nothing happens. No path bookkeeping, no mtime comparison, no pausing the watcher across a write — all three of which race. `notes-editor.md` §Open question 2 is closed by this.

- [ ] **Step 2: Run, fail, implement, run, green**

- [ ] **Step 3: Write the failing tests — clean reloads, dirty merges, overlap conflicts**

Clean buffer (`buffer === base`) takes disk silently — the common case, because autosave fires on idle. Dirty buffer runs `merge3(base, buffer, disk)`. An unmergeable overlap returns its regions and routes to the vault's ordinary reconcile affordance.

- [ ] **Step 4: Implement, run, green, commit**

- [ ] **Step 5: Strip yjs and the collab provider out of `EditorPane`**

`yjs` and `y-codemirror.next` are **not dependencies** — the imports have been dead since the D60 pivot. `../collab/provider` and `../state/sync` do not exist. Delete rather than replace: `merge3` is what replaced the CRDT, and it is already built and tested.

- [ ] **Step 6: Wire load/save through `notes.read` / `notes.write`, advancing `base` on both**

`base` is the text the editor last **loaded or saved** (`glossary.md` §3-way reload). Advancing it on save is what makes Step 1's no-op work.

- [ ] **Step 7: Wire the FR-6 flush points**

Idle debounce and ⌘S write the buffer (FR-4 — ⌘S is a real commit point, so it also calls `sync.commitNow`). Tab close, vault switch and window blur flush. **Publish flushes first, then calls `sync.publish`** — main commits before pushing (plan 4 §Resolved, D1), but it can only commit what is on disk.

- [ ] **Step 8: Wire `vault.onFlushRequest` → write every dirty buffer → `vault.flushDone()`**

Main's half is done and tested (`main/flush.ts`). It waits **1 second** and then quits regardless, so this handler must not await anything slow — and must call `flushDone()` even if a write throws, or a failed save silently becomes a one-second pause on every quit.

- [ ] **Step 9: Run the suite, commit**

**Gotchas:**
- The snapshot push carries **no path** — it is the whole vault, every time. The editor re-reads its own file when one arrives; it cannot ask "was it me?" and does not need to.
- Do not reload on your own save. Step 1 is the whole defence, and it works only if `base` advances on save *before* the watcher event lands.

## Gotchas that apply throughout

- **Bare `node` and `npx` are broken on this machine — use `pnpm exec`.**
- **The shell's cwd resets between `Bash` calls.** Use absolute paths or an explicit `cd` in every command. Half a dozen commands failed this way in plan 4 and again in this session's Task 1.
- **Backticks in a `git commit -m` heredoc get shell-substituted** and silently eat words. Write the message to a file and use `-F`.
- **`pkill` must be scoped** — the agent's own host is Electron. `pkill -f "better-holi-final/node_modules/.pnpm/electron@"`, never a bare `pkill -f electron`. Verify with `pgrep -f better-holi-final`.
- **`electron-vite` resolves imports but does not typecheck.** A quarantined file is quarantined only as long as nothing on the boot path imports it, and the compiler will not tell you when that breaks — the window simply fails to open.
- **Vitest 4 ignores `poolOptions.forks.singleFork`.** `fileParallelism: false` is the lever, and it is already set.
- **`docs/decisions.md` next free number is D61.** Plan 4 spent none; its decisions live in its plan doc, and this one should do the same.

1. **Where the tab strip persists.** `.holi/settings.local.json` is the obvious home (machine-local, gitignored), but whether tabs survive a restart is a product call — and plan 7 owns preview-vs-pinned anyway.
2. **Undo across an external reload.** `notes-editor.md` §Open question 3. A `merge3` result replacing the buffer wrecks CodeMirror's undo history; whether that matters enough to reconstruct is unknown until someone has lived with it.
3. **Task files in the tree.** `notes-editor.md` §Open question 1 — whether `task.*.md` shows as an ordinary note. Plan 5 renders them; if that reads badly in the running app, plan 7 is where it changes.
