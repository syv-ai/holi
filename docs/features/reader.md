# Read all the things

A Word document (`.docx`), a PowerPoint deck (`.pptx`) or an EPUB book (`.epub`) opens in a tab to read, drawn as faithfully as the browser can, and nothing in it is ever changed. It is the plugin `reader`, on by default; with it off, those files show the same placeholder as any other office format, saying which plugin to turn on. Which paths it takes is one shared rule, `readableDoc`, which the placeholder asks too.

## How it works

**Bytes.** Main reads the file through core's `files.read`, as the PDF viewer does, and the renderer draws it; the plugin has no main side beyond its name. While the bytes are on their way the pane shows a page-shaped skeleton; a read that fails is the shared error with Retry. A file that changes on disk under its tab (a pull, another tool) is read again and drawn afresh. A file over the 10 MB commit limit, held back from sync, opens like any other. Each format's renderer is its own lazy chunk, so opening a Word file never loads the deck or book renderer, and the app's main chunk carries none of them.

**Word.** `docx-preview` draws the document into an inert frame (below), page by page on the theme's muted canvas, with Word's own page breaks from its last save. A page wider than the pane is scaled down to fit it, never up. Images come out of the file as `data:` URLs; comments are not drawn, and an alt chunk (a whole HTML document embedded in the file) is never drawn. `patches/docx-preview@0.4.1.patch` fixes two parser bugs until releases have them: a style's own properties no longer lose to its base style's (docxjs#259), and content controls in tables are no longer dropped (docxjs#253).

**PowerPoint.** `@aiden0z/pptx-renderer` draws every slide one under another into an inert frame, fitted to the pane's width, with slides and media parsed only as they are drawn and the recommended zip limits for untrusted archives. It blocks every external media relationship (`externalMedia: 'block'`) and never loads PDF.js (`pdfjs: false`). Charts are drawn by echarts as SVG: a `<canvas>` in a document with scripting disabled shows only its fallback content, so canvas charts stay blank in the frame. Until the renderer's `chartRenderer` option is released (aiden0z/pptx-renderer#56), `patches/@aiden0z__pptx-renderer@1.4.0.patch` makes it use echarts' SVG renderer. The same patch gives a plain text box the presentation's default text size rather than the master's `otherStyle`, which is for table text, as Apple's and LibreOffice's renderers do (aiden0z/pptx-renderer#57), and a picture placeholder with no shape of its own takes its layout placeholder's shape (aiden0z/pptx-renderer#58). A deck's embedded fonts register on the app's document, not the frame's, so its slides use the system's fonts.

**EPUB.** foliate-js, vendored at a pinned commit under `renderer/vendor/foliate/` (its `vendored.md` lists the commit and Holi's three changes), lays the book out a page at a time, reflowable and fixed-layout alike. The toolbar has the book's contents (a part with chapters of its own is a submenu), the chapter's name, how far in the reader is, and previous and next; the arrow keys turn the page too, from the pane or from inside a chapter. A theme button on the toolbar steps through the reading themes: Light, Sepia and Dark set the page and force the text colour, so a book that prints black text stays readable on a dark page; App gives the app's own text colours (resolved from its tokens, since a chapter cannot read them, and set again when the mode flips) and lets the book's CSS still set its colours; Book default shows the book as published on a white page. App is the default, and the choice is this machine's (`holi.reader.epubTheme` in local storage). A book reopens where it was last read on this machine: its location (an EPUB CFI) per vault and path, saved on every page turn in local storage (`holi.reader.epubPositions`, the 200 most recently read books).

**Shortcuts** pressed inside a frame (⌘W, ⌘K, ⌘F) are sent on to the app, which would otherwise never hear them.

## Rules

- **No script from a file ever runs.** Every frame that holds a file's content is `sandbox="allow-same-origin"` and nothing else: Holi's script builds the content into the inert document. Granting `allow-scripts` as well would let the content drop its own sandbox. foliate's chapter frames ship with `allow-scripts` for a WebKit bug; the vendored copy is patched back, and a test fails if any `sandbox` there grants more. A script a book lists is never unpacked.
- **Nothing outside the file loads.** Every such frame, and every EPUB chapter as it is unpacked, carries one policy (`INERT_CSP` in `inert-frame.ts`): `default-src 'none'`, with images, media, fonts and styles only from `data:` and `blob:`, which is what the renderers make of what the file packs. docx-preview and the deck renderer build their nodes with the app's `document` before moving them into the frame, so for Word and PowerPoint the first guard is the libraries' own: docx-preview fetches nothing, and the deck renderer runs with `externalMedia: 'block'`. Before a book opens, every manifest media type is brought to its plain lowercase form (`epub-chapters.ts`), so a chapter spelled `Application/XHTML+XML`, with a parameter, or as `application/xml` is still parsed and given the policy; a page that is not markup, such as an SVG, which cannot carry a policy, is shown as an `<img>` inside a page that does. The chapter's policy is put in with a real parser, first in its head, so a `<head>` in a comment cannot move it. foliate copies a chapter's background onto an element in Holi's own document; the vendored copy takes only the colour, since a `url()` there would load outside the policy (johnfactotum/foliate-js#169).
- **A link never navigates a frame.** Any link counts, `a`, an image map's `area` and an SVG link's `xlink:href` alike. A web or mail link opens in the browser (main's `openExternal` refuses anything else whatever it is sent), a link within an EPUB turns to it, a Word bookmark or contents entry scrolls to its place, and anything else, `javascript:` and `file:` included, does nothing. The deck frame takes a click on a link before the renderer's own handler; a shape's hyperlink is not a link element, and the renderer opens it with the app's `window.open`, which the window guard turns into the browser for a web or mail address and refuses otherwise.
- **Read-only.** The plugin never writes a file; there is no agent verb and no row-menu action.
- **No retained state.** Like the PDF viewer, a viewer is drawn afresh when its tab is shown again: a file claim is not a kept-mounted surface. A book comes back at its saved place; Word and PowerPoint files open at the top.
