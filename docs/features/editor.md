# Editor

Every note is a `.md` file, edited in ReUI's rich-text editor (Tiptap) on the documents tab. The editor writes the file directly, autosaves, and survives the file changing underneath it. CodeMirror 6 edits the other text files and the Google plugin's mail composer.

## The documents tab

A `.md` file opens in ReUI's rich-text editor (`rich-text-editor-2`, Tiptap) rather than CodeMirror: `features/documents/`, the editor itself in `features/documents/rich-text/`. The file is still the source of truth.

- **Markdown in, markdown out.** Only the body passes through the editor. The frontmatter block is kept byte for byte and put back on save (`markdown.ts`), since the editor neither shows nor understands it. The body round-trips through `@tiptap/markdown` and each extension's own rules, plus three the block lacks (`document-extensions.ts`): `[[wiki links]]` as chips written back as typed (otherwise the serializer escapes the brackets), made a chip too as a typed link's `]]` lands or when one is pasted (`wiki-link.ts`'s input and paste rules), since text left as `[[…]]` would be saved escaped, images whose path stays as written and loads through `holi-vault://`, and raw HTML blocks kept verbatim. Text alignment is left out: markdown cannot say it. A file's formatting is normalised the first time it is edited here (a table's divider row padded to its columns), never on open alone.
- **Saving and outside changes.** Typing saves after a pause. A change on disk (a pull, the agent) is read back in unless local edits are still pending, which win.
- **Keys.** "/" opens the block menu. ⌘B is always the editor's, bold where bold applies, so it never reaches the shell's sidebar toggle. ⌘K opens the link field in the format bubble. ⇧⌥↓ duplicates the caret's block (VS Code's copy line down; the block menu's Duplicate says so), since ⌘D selects occurrences.
- **Find (⌘F, Ctrl+F elsewhere).** ⌘F anywhere in a document's view, the text or its header, opens that view's own find bar at the top right of the page, so each view of a split has its own; the shell's table has no ⌘F and the menu binds none. The engine is `prosemirror-search` (`document-find.ts`), the sibling of CodeMirror's search: it holds the query and paints every match on document positions, so a match in a link, a mark or a list item maps exactly. The bar (`document-find-bar.tsx`) is a small Card of installed parts: the query field (seeded from the selection when it is one line) with the count ("3 of 12", "No results") and the Match case, Whole word and Regular expression toggles inside it, then previous, next and close. Typing selects the first match from where the caret was and scrolls to it; Enter or ⌘G steps forward, ⇧Enter or ⇧⌘G back (also from the text while the bar is open), wrapping. Escape, in the bar or the text, closes it and gives the editor focus with the match selected; ⌘F in the bar selects its field. The arrow at its start opens Replace, with Replace (Enter) and Replace all (⌘Enter); a locked page has no replace. Every match is tinted `--find-match`, the selected one `--find-match-current`, both mixed from `--warning` in `index.css`.
- **Next occurrence (⌘D, Ctrl+D elsewhere).** With a caret ⌘D selects the word under it; with a selection each press adds the next occurrence of its text, wrapping, as VS Code does. A word picked from a caret matches whole words only; a selection you made matches anywhere, case-sensitively. ProseMirror has one selection, so the newest occurrence is the editor's own (scrolled to) and the earlier ones are ranges `multi-cursor.ts` keeps and draws (the blurred selection's tint, a 1px caret). Typing, Backspace, Delete, ← → and a one-line paste edit every one at once, as one undo step; a caret at its block's edge does not join blocks. Anything else, Enter, Tab, ↑ ↓, a click, a composition, lets the others go and acts on the newest alone, so a block key never acts on a place it cannot see; Escape collapses to it. The format bubble stays away while there are several, since its marks would reach only one; Space types a space at each rather than asking the agent.
- **The agent.** Space on an empty top-level line (or "/" Ask AI) opens a prompt there; sending it writes a `<!-- holi:agent -->` line where it was asked, saves, and starts a background Claude Code session on Sonnet 5.5 through the agent plugin's `agent.launch`, allowed to read and edit that one file and nothing else (`document-agent.ts`). The format bubble's Ask AI rewrites a selection the same way (improve, fix spelling and grammar, simplify, shorten). While either runs the page is locked: the editor is read-only and nothing in the view can be pressed. A pill at its foot says what the run is doing, read off the session's state (starting, writing, waiting for you in Agents, done), with Stop. A run that ends without removing its marker has it removed.
- **The header.** Name, folder and save state on the page's own ground with a hairline under it; who has written the file (GitHub's commit authors with avatars, the local log's names when GitHub cannot answer: `github.fileContributors`); undo and redo; and a menu with Full Width, Small Text, Copy Markdown (the whole file), Copy HTML, and Turn into an Artifact, which has the agent make `<name> Artifact.app` beside the document, a vault app, without changing the document.
- **The page.** A press anywhere below the text starts a new line there; beside the text it places the caret on the nearest line.

## How it works

**Two CodeMirror stacks** (`editor/extensions.ts`). `plainTextExtensions` opens a text file that is not a note (`.json`, `.csv`, `.env`) with highlighting and a validity check for known formats, no markdown layers. `plainMarkdownExtensions` is markdown editing with no vault layer, for text that leaves the vault (the mail composer, through the plugin api): GFM tables and fence highlighting, but no wiki-link chips and no `@` completion, which would paste vault paths into an email.

**Files that are not notes.** A file that is not a note opens in the file viewer (`features/files/file-view.tsx`): a plugin's claimed view first (a PDF in the viewer, [pdf.md](pdf.md)), an image in its own tab, other known binaries in a typed placeholder, and any other text (css, yaml, json, `.vue`, `.gitignore`, `.env`) as code, editable on arrival like a note: the plain editor dressed as ReUI's code block (`code-look.ts`: the block's own Shiki highlighter and GitHub themes, so Vue and Svelte colour too, its 13px mono on 24px lines, the numbers muted in its gutter, no soft wrap), autosaved shortly after the last keystroke and held while json or yaml does not parse. ⌘F opens the same find bar a document has (`composites/find-bar.tsx`), over the code: match case, whole word, regular expressions, a count, ⌘G and ⇧⌘G, and a replace row; CodeMirror's own search steps and replaces (`features/files/code-find.ts`), its panel never opened.

**History.** A document's header and a code file's carry the same history (`features/history/`): the latest commit, `4a14110 · 2 hours ago`, and History, a dialog after GitHub's commits page. Its commits are grouped by day on a timeline and filtered by author and by time; each row copies its SHA, opens what it changed in the file, or shows the file as it left it, all in ReUI's code block (`lineDiff` against the commit's parent; Shiki with the grammar `editor/languages.ts` picks, plain past 300 KB). The code block's grammars are written out one per line in `code-block-highlight.tsx`, each its own lazy chunk; a new language is a new line there. Binaries stay out of the link graph.

**Ask the agent.** The message is your instruction, then `[From <path>, lines 12-18]` and the passage quoted with `> ` (`askPrompt` in `lib/ask-agent.ts`, which the plugin api re-exports).

**Saving.** Written after 600 ms of quiet and on blur, flushed on tab close, vault switch and quit. ⌘S saves every buffer, commits and pushes. Invalid frontmatter YAML holds the save; a flush writes anyway.

**External writes.** In a document, a change on disk (a pull, the agent) is read back in unless local edits are still pending, which win (`document-view.tsx`). It comes in as a co-author's edit (`apply-reload.ts`): only the range from the first difference to the last is replaced, so a caret outside it stays on its text rather than landing at the end, and the reload is no undo step. Edits on both sides of the caret still move it. The commit's own tidy (`normalize-md`) is not a change at all: a file that differs from what was saved only by what the tidy strips leaves the buffer alone, so a space typed before a pause survives the commit, and a buffer that differs only that way is not written back (`differsBeyondTidy`). A file edited while a tab is not shown is compared the same way (`differsBeyondTidy`, `state/doc-changes.ts`) so the tidy alone is not reported as a change. **Not built:** the 3-way reload that merged a dirty buffer with the file (`merge3`, a conflict banner with Keep mine and Use the file on disk); `merge3` stays in `packages/shared` and the agent's turn review uses it. See [not-built](../not-built.md).

## Rules

- Only normalization counts as our own write. It is idempotent; a `relink` rewrite carries real content.
- Completion chrome is scoped by the `cm-holi-completion` class to outrank CodeMirror, holds no hex, and keeps `icons` on (the table menu styles off it).

## Rejected

- Rendering every binary in place, or converting PDFs to markdown on entry: the agent cannot read them.
- Our own completion engine or a React overlay: Radix menus take focus the editor must keep.

- `apps/desktop/src/renderer/src/state/doc-changes.ts`: what changed on disk while a tab was not shown
- `packages/shared/src/merge3.ts`, `normalize-md.ts`, `file-kind.ts`, `image-ref.ts`
- `apps/desktop/src/renderer/src/features/files/file-view.tsx`: every file that is not a note or an app
