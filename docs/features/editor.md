# Editor

Every note is a `.md` file, edited in CodeMirror 6 with live preview: markdown renders inline, and the element under the caret shows its raw source. The editor writes the file directly, autosaves, and survives the file changing underneath it.

## The documents tab

The fresh shell opens a `.md` file in ReUI's rich-text editor (`rich-text-editor-2`, Tiptap) rather than CodeMirror: `components/blocks/document-view/`. The file is still the source of truth.

- **Markdown in, markdown out.** Only the body passes through the editor. The frontmatter block is kept byte for byte and put back on save (`markdown.ts`), since the editor neither shows nor understands it. The body round-trips through `@tiptap/markdown` and each extension's own rules, plus three the block lacks (`document-extensions.ts`): `[[wiki links]]` as chips written back as typed (otherwise the serializer escapes the brackets), images whose path stays as written and loads through `holi-vault://`, and raw HTML blocks kept verbatim. Text alignment is left out: markdown cannot say it. A file's formatting is normalised the first time it is edited here (a table's divider row padded to its columns), never on open alone.
- **Saving and outside changes.** Typing saves after a pause. A change on disk (a pull, the agent) is read back in unless local edits are still pending, which win.
- **Keys.** "/" opens the block menu. ⌘B is always the editor's, bold where bold applies, so it never reaches the shell's sidebar toggle. ⌘K opens the link field in the format bubble. ⇧⌥↓ duplicates the caret's block (VS Code's copy line down; the block menu's Duplicate says so), since ⌘D selects occurrences.
- **Find (⌘F, Ctrl+F elsewhere).** ⌘F anywhere in a document's view, the text or its header, opens that view's own find bar at the top right of the page, so each view of a split has its own; the shell's table has no ⌘F and the menu binds none. The engine is `prosemirror-search` (`document-find.ts`), the sibling of CodeMirror's search: it holds the query and paints every match on document positions, so a match in a link, a mark or a list item maps exactly. The bar (`document-find-bar.tsx`) is a small Card of installed parts: the query field (seeded from the selection when it is one line) with the count ("3 of 12", "No results") and the Match case, Whole word and Regular expression toggles inside it, then previous, next and close. Typing selects the first match from where the caret was and scrolls to it; Enter or ⌘G steps forward, ⇧Enter or ⇧⌘G back (also from the text while the bar is open), wrapping. Escape, in the bar or the text, closes it and gives the editor focus with the match selected; ⌘F in the bar selects its field. The arrow at its start opens Replace, with Replace (Enter) and Replace all (⌘Enter); a locked page has no replace. Every match is tinted `--find-match`, the selected one `--find-match-current`, both mixed from `--warning` in `index.css`.
- **Next occurrence (⌘D, Ctrl+D elsewhere).** With a caret ⌘D selects the word under it; with a selection each press adds the next occurrence of its text, wrapping, as VS Code does. A word picked from a caret matches whole words only; a selection you made matches anywhere, case-sensitively. ProseMirror has one selection, so the newest occurrence is the editor's own (scrolled to) and the earlier ones are ranges `multi-cursor.ts` keeps and draws (the blurred selection's tint, a 1px caret). Typing, Backspace, Delete, ← → and a one-line paste edit every one at once, as one undo step; a caret at its block's edge does not join blocks. Anything else, Enter, Tab, ↑ ↓, a click, a composition, lets the others go and acts on the newest alone, so a block key never acts on a place it cannot see; Escape collapses to it. The format bubble stays away while there are several, since its marks would reach only one; Space types a space at each rather than asking the agent.
- **The agent.** Space on an empty top-level line (or "/" Ask AI) opens a prompt there; sending it writes a `<!-- holi:agent -->` line where it was asked, saves, and starts a background Claude Code session on Sonnet 5.5 through the agent plugin's `agent.launch`, allowed to read and edit that one file and nothing else (`document-agent.ts`). The format bubble's Ask AI rewrites a selection the same way (improve, fix spelling and grammar, simplify, shorten). While either runs the page is locked: the editor is read-only and nothing in the view can be pressed. A pill at its foot says what the run is doing, read off the session's state (starting, writing, waiting for you in Agents, done), with Stop. A run that ends without removing its marker has it removed.
- **The header.** Name, folder and save state on the page's own ground with a hairline under it; who has written the file (GitHub's commit authors with avatars, the local log's names when GitHub cannot answer: `github.fileContributors`); undo and redo; and a menu with Full Width, Small Text, Copy Markdown (the whole file), Copy HTML, and Turn into an Artifact, which has the agent make `<name> Artifact.app` beside the document, a vault app, without changing the document.
- **The page.** A press anywhere below the text starts a new line there; beside the text it places the caret on the nearest line.

## How it works

**Three stacks.** `baseEditorExtensions` is the notes editor. `plainMarkdownExtensions` is the same markdown editing with every vault layer removed, for text that leaves the vault (the Google plugin's mail composer, through the plugin api). `plainTextExtensions` opens other text files with highlighting and validity checks, no markdown layers.

**Live preview.** A `ViewPlugin` decorates the visible ranges and rebuilds on doc, selection or viewport change. The **element** the selection touches renders raw; the rest of its line stays rendered. Touching an edge counts, and when elements nest only the innermost opens. A heading's `#`, a list marker and a quote's `>` reveal with their whole line. The swap is instant, except the marks that move a whole line's text: a heading's `#`, a quote's `>` and a fence's backticks slide (`mark-slide.ts`). Each is a mark that is never replaced, opened by its own line class (`cm-heading-raw`, `cm-quote-raw`, `cm-code-raw`), so a fence inside a quote opens only what the caret is on. Inline marks (`**`, a link's `](url)`) and rendered widgets stay a plain swap: they have no line of their own to carry the state, and a long URL would rewrap its paragraph for the length of the slide.

**Keys and links.** ⌘B, ⌘I, ⌘E, ⌘⇧X (or ⌘⇧S) and ⌘U wrap or unwrap the selection or word; ⌘K opens the link field. A wiki-link chip opens on click; a markdown link needs ⌘-click, since a plain click means "edit this text". A bare `github.com`, `www.` or `https://` address in prose opens the same way; `linkify-it` finds them, without emails and without the country domains that are also source-file extensions (`notes.md`, `main.py`). Code, comments and existing links are skipped, and the file is left as written. All three forms look alike: everything inside a link takes the link's colour, since GFM parses `www.` and `https://` addresses as `URL` nodes that the code highlighter would otherwise paint.

**Arrows are rewritten as you type.** `->` becomes `→` in the file once the space after it goes in, and `<-`, `<->` and `=>` become `←`, `↔` and `⇒`. Only with whitespace or the line's start before it, never in code or frontmatter. It is its own undo step, so ⌘Z gives back the typed arrow.

**Lists.** Nesting comes from the tree, never from counting spaces; the typed indentation is concealed and depth alone places a line. An item's wrapped rows and its later lines (a soft break, a lazy continuation) hang under its text. Every marker sits in a box of known width, so no measuring is needed: a bullet, a checkbox, an ordered marker as wide as its list's longest in `ch` with tabular digits, so `9.` and `10.` share a column. The one space after a marker is concealed and the theme's gap stands in for it, since its width is the font's. `a.`, `A.` and `a)` lists are Holi's own, since CommonMark has only decimal ones: a parser extension (`alphaLists` in `lists.ts`) puts them in the tree as an `AlphaList` of ordinary `ListItem`s, so they nest, wrap and continue like any list. One may start inside a list or at the start of a block, never mid-paragraph, so "A. Smith said" stays a sentence. Markdown's own Enter cannot write a letter, and builds its indent only from lists it knows, so Enter in a letter list, or in any list inside one, is Holi's.

**A list's kind is chosen by typing it.** In the empty first item of a list, typing `a.` after the marker makes it a letter list (`1. a.` becomes `a. `), and `1.` makes it decimal again; `A.`, `a)` or any number work too, and set where the list starts. Only the first item chooses, so `2. a.` stays text, and the rest of the list follows it. The switch is its own undo step, so ⌘Z gives back what was typed. Bullets are not offered: an empty `- ` under a line of text is that line's setext underline, so switching would turn it into a heading.

**Ordered numbers are rewritten in the file.** After an edit that reshapes a list (Tab, Shift+Tab, Enter, deleting a marker or a line break, moving a line), a transaction filter renumbers every decimal or letter list it touched from its start. A list keeps its start only if its first item was already one; otherwise it starts at 1. A nested list with no blank line above it always starts at 1, because CommonMark, GitHub included, reads `2.` under an item's text as more of that text. Letters keep the case of the list's first item and stop at `z`. Typing inside an item, a number included, is left alone, as are undo and reloads.

**Tables** (`codemirror-markdown-tables`) sit centred in the column, their cells keeping their own alignment; a table wider than the column scrolls from its left edge. A focused cell is a nested editor given inline live preview under `inlineOnlyFacet`. An unfocused cell is rendered by the package from the root highlighter, so a `HighlightStyle` is the only thing that styles it: it can hide `**`, `*` and `` ` ``, and keeps a link's brackets. The app-wide stable scrollbar gutter skips a cell's editor, whose scroller is `overflow: hidden`: the reserved lane widened a cell as it took focus, and the centred table shifted with it. The package pads a table's columns and the blank lines around it; Holi patches it (`patches/codemirror-markdown-tables@1.0.0.patch`) so it does that only to a table your own edit touched. It draws only a table already in that form, so a table written elsewhere unpadded (by GitHub, the agent, a teammate) shows as its markdown until you edit it; the first edit pads it and the widget takes over. Opening a note, moving the caret and an external write (a pull, the agent) leave every table byte for byte as written: the package formatted any table on a note's first update, and the autosave then rewrote a file nobody had edited; and its boundary correction, applied to a reload that rewrote a table's first line, mapped the table's old span into the new text and split a row in two.

**Images and binaries.** Any file may live in a vault; markdown is what you write. `![](path)` (note-relative) and `[[img.png]]` (vault-relative) render inline via `holi-vault://`. A file that is not a note opens in the file viewer (`file-view.tsx`): a plugin's claimed view first (a PDF in the viewer, [pdf.md](pdf.md)), an image in its own tab, other known binaries in a typed placeholder, and any other text (css, yaml, json, `.vue`, `.gitignore`, `.env`) as code, editable on arrival like a note: the plain editor dressed as ReUI's code block (`code-look.ts`: the block's own Shiki highlighter and GitHub themes, so Vue and Svelte colour too, its 13px mono on 24px lines, the numbers muted in its gutter, no soft wrap), autosaved shortly after the last keystroke and held while json or yaml does not parse.

**History.** A document's header and a code file's carry the same history (`file-history/`): the latest commit, `4a14110 · 2 hours ago`, and History, a dialog after GitHub's commits page. Its commits are grouped by day on a timeline and filtered by author and by time; each row copies its SHA, opens what it changed in the file, or shows the file as it left it, all in ReUI's code block (`lineDiff` against the commit's parent; Shiki with the grammar `code-language.ts` picks, plain past 300 KB). The code block's grammars are written out one per line in `code-block-highlight.tsx`, each its own lazy chunk; a new language is a new line there. Binaries stay out of the link graph.

**Inline code** is the prose's size, in mono scaled to the prose face's x-height (`font-size-adjust: from-font`), with no fill: the `--code` theme token colours it.

**Quotes** are a flat translucent surface, holding what the quote holds (lists hang inside it as outside). The `> ` shows only on the caret's line. A quote and a fenced block are the note's two filled blocks and share one geometry: the fill starts just outside the text's edge (`--block-inset`, 8px short of the column's inset) on both sides, so their own text sits a step in, and only their first and last lines round their corners.

**Comments.** An HTML comment on lines of its own draws as a small floating banner, centred, in the `--comment` and `--comment-background` tokens, and shows its source when touched. One inside a paragraph stays text in the comment colour. The banner is exactly as tall as its source, whose first and last lines take the banner's padding while they show, so opening a comment does not move the note.

**Fenced code** hides its backticks while the caret is outside the block, leaving the language as a small label. The fence lines stay, so the block keeps its height when the caret enters and the fences show. Its fill is the foreground at 4% (the house `[0.04]` step), so it shows in light as well as dark.

**Mermaid.** A mermaid fence draws as a diagram and shows source when touched. Mermaid loads on first use, a broken diagram shows its source, and the palette follows light/dark at render time.

**The page editor** follows ReUI's `rich-text-editor-2` block (its Tiptap page editor with slash commands, mentions, tables and an outline rail), rebuilt on CodeMirror over markdown. Every one of its features either writes the markdown you could have typed, or is a view setting that never reaches the file. Where markdown has no syntax, Holi writes the form GitHub and other renderers already read, so the file stays portable and the agent reads what you see.

**The slash menu** (`slash.ts`, after ReUI's) comes from `holiCompletion`, like every popup in the app. `/` at a line's start or after a space opens it, never in code or the frontmatter. Basic blocks: Text, Heading 1–3, Bullet list, Numbered list, To-do list, Quote, Code block, Divider; Advanced: Table, Contents. Every label in the editor's menus is sentence case, as the rest of the app's are. Each row has its glyph on a small tile, its name over a one-line hint, and at the end the markdown that makes the same block by hand. The query matches a name anywhere or a keyword from its start, so `/todo` and `/table` still go straight to theirs; nothing matching says so, and Enter there is a plain Enter. A pick removes the typed `/query` and turns the caret's block as Turn into would, in one undo step; on an empty line it makes the block fresh. A divider or a Contents line goes on a line of its own with a blank line around it, since `text` over `---` is a heading. Table reopens on sizes (columns by body rows). `@` lists notes, then open tasks, and inserts a `[[path]]`.

**Blocks** (`blocks.ts`). A block is a run of whole lines: the innermost list item at a position, with its children, or else the top-level node (a paragraph, a heading, a fence, a quote, a table). Every block action reads the syntax tree and rewrites lines, so it is one undo step and the file is still the markdown it was. Moving keeps the gap between siblings (a line break between items, a blank line between blocks), and an ordered list it touches is renumbered by the same filter as Tab.

**The block gutter** (`features/editor/BlockGutter.tsx`, after ReUI's) follows the pointer to the block's first line, left of its text, so a list item's clears its marker. `+` opens an empty row below and types `/` in it (⌥ adds above; an empty item is reused rather than doubled). The grip drags the block: it fades, a 2px line shows where it lands, and the drop moves its lines. An item dropped beside another joins that list at its depth and takes its marker kind; a paragraph dropped on an item lands beside the whole list, since nothing but items sits between items. Clicking the grip, or ⌘/, opens the block menu: the block's name, Turn into (Text, Heading 1–3, Bullet, Numbered, To-do, Quote, Code block), Duplicate, Move up and down, Delete. A table asks first, naming the heading above it, and then offers Undo. While the menu is open the block is tinted like a selection. Typing hides the gutter until the pointer moves; a locked or read-only page has none.

**The selection bubble** (`formatBar.ts`, after ReUI's format bubble). A selection shows one bar over it: the block's type (Text, Heading 1–3, ⌘⌥0–3), Bold ⌘B, Italic ⌘I, Underline ⌘U, Strikethrough ⌘⇧S (and ⌘⇧X), Inline code ⌘E, alignment (⌘⇧L, E, R, J), Highlight ⌘⇧H, Link ⌘K, then Ask agent after a hairline when there is an agent. A toggle shows pressed when its mark holds the selection. Its menus and popovers are panels inside the bubble, not Radix overlays, so a press keeps the selection painted. The link field validates (a web, mail or phone address; a bare domain gets `https://`), says what is wrong, applies, and removes; with nothing selected the address becomes its own link text. Alt+F10 reaches the bar from the text, ← → walk it, ↓ opens a menu, Escape steps back out. In code the marks step aside and Ask agent stays. Each control has a tooltip with its key.

**Marks markdown has no syntax for** (`marks.ts`). Highlight is `==text==` for yellow, which needs a parser extension since CommonMark has no `==`, and `<mark data-color="green">text</mark>` for green, blue, pink and violet; each colour is ReUI's light and dark pair. Underline is `<u>text</u>`. Both are inline HTML, which GFM keeps, and live preview hides their tags until the caret is on them, as it does `**`. Alignment wraps a top-level paragraph or heading in `<div align="center">` with a blank line inside each end, because without the blank line CommonMark reads the run as raw HTML and its links and emphasis stop working. Off the caret the wrapper's tag lines fold away with the blank line beside each (a block decoration from a state field), so a centred paragraph reads as only that; with the caret anywhere in the wrapper they show, small and quiet, to be edited like any other syntax under the caret. Only a wrapper written that way folds, so a hand-written one without its blank lines never hides text. The gutter and block menu take the wrapper and its text as one block: moving, duplicating or deleting it carries the tags along, and Turn into rewrites only the text inside. A list item cannot be aligned: a wrapper would end its list.

**The caret's link** (`linkBubble.ts`) shows its address, which opens it, then Edit (the bubble's link field on the link) and Remove (keeps the text). Only an address `normalizeHref` accepts goes live.

**The Contents block** (`contents.ts`). A `[toc]` line on its own (Typora's and Python-Markdown's spelling) draws as the note's headings, each a link that jumps to it, indented by level, kept live; with none it says how to get some. It shows its source while the caret is on it, like a mermaid fence.

**A done task** reads as done, as ReUI's task item does: its box ticked, its text muted and struck through.

**The line hint.** The caret's empty line reads "Type / for commands", an empty heading its level ("Heading 2"), only while the editor has focus.

**Space asks the agent** (`askSpace.ts`; not in ReUI, after Notion's AI). On an empty line of prose, outside a list item, a fence, a table and the frontmatter, Space opens a field under the line instead of typing a space, and the line's hint says so. Enter sends what was written to a new agent session, with `[From <path>, line N]` after it, the way a selection ask carries its lines; Shift+Enter is a newline. Enter, not ⌘↵ as in the selection's field: this is a one-line request typed where a sentence would have been, and a newline is rarely wanted. Escape closes it and types the space after all, so nothing is lost; moving away closes it. It needs an agent and a writable file, and the `spaceAsksAgent` setting (on by default, machine-local, see [settings](settings.md)) turns it off.

**The page controls** (`features/editor/PageActions.tsx`, after ReUI's page header and actions) sit in the editor's top corner: Saving… or Saved (as the autosave goes), Locked when locked, Undo and Redo, the outline as a button where the pane is too narrow for the rail, and the page menu. Full width lifts the column's cap; Small text sets the page a step down (14px); Lock page makes it read-only and takes the bubble and gutter away. Export copies the page as HTML (GFM, wiki-links as their labels), as plain text, or as its markdown, and says Copied in place. Clear page asks first, keeps the frontmatter, and offers Undo for 8 seconds. That Undo, and a deleted table's, is a toast from the shell's one `Toaster` (`primitives/Sonner.tsx`, shadcn's `sonner`): its live region is in the page before the message arrives, so a screen reader announces it, where a notice mounted with its text already inside often went unheard. **The three toggles are machine-local**, per vault and note (`state/note-page.ts`), like pins: how wide one person reads and a guard on their own keystrokes are not facts about the note, and in frontmatter they would be committed, shown to everyone and the agent, and make a view setting a git change. A read slower than a beat shows the page's shape while it loads.

**Keys.** Beyond the marks: ⌘⇧↑ and ⌘⇧↓ move the caret's block (as in Notion and ReUI, in place of extending the selection to the document's ends), ⌘D duplicates it from a caret while ⌘D with a selection keeps adding the next occurrence, ⌘/ opens the block menu (toggle comment stays on ⇧⌥A), ⌘⇧7, 8 and 9 make a numbered, bullet or to-do item, ⌘⇧B a quote, ⌘⌥C a fence. A block key on a block already of that kind turns it back into text.

**The outline rail** (after ReUI's page editor, `features/editor/OutlineRail.tsx`). From two
headings up, the editor's right edge carries one short tick per heading, longer for a higher level,
the section at the top of the screen lit. Hovering or focusing it opens the contents beside it on
the menus' surface, indented by level; a heading there scrolls to it and puts the caret on it. The
headings come from the syntax tree (`editor/outline.ts`), so a `#` in a code fence or the
frontmatter is not one, and they are re-read once typing pauses. The list is one tab stop, on
the current heading; ↑ ↓ Home End move inside it. Below 640px of pane the rail would sit on the
text, so the page controls carry the outline as a button instead.

**Ask the agent.** Ask agent in the selection bubble opens a field and a session picker. The message is your instruction, then `[From <path>, lines 12-18]` and the passage quoted with `> `; line numbers come from CodeMirror's range, so they are exact.

**Saving.** Written after 600 ms of quiet and on blur, flushed on tab close, vault switch and quit. ⌘S saves every buffer, commits and pushes. Invalid frontmatter YAML holds the save; a flush writes anyway.

**External writes.** `base` is the text last loaded or saved. `decideReload`: disk equal to base is nothing; a clean buffer reloads; a dirty one takes `merge3`; an overlap raises the conflict banner (Keep mine, Use the file on disk, Dismiss). Disk equal to `normalizeText(base)` is the pre-commit tidy: base catches up and the buffer is kept, clean or not. The commit lands seconds after autosave, while someone who stopped to think is still looking at the line, so taking the tidied bytes would pull a just-typed space out from under the caret. A markdown buffer that differs from base only by the tidy has nothing new, so it is not written back (`hasNewText`). The tidy itself keeps the one space after a bare list marker or `#`, since without it the line would stop being an item or a heading. A reload is a minimal diff with `addToHistory: false`, so the caret stays and ⌘Z unwinds only your keystrokes.

**The column** is about 70 characters of the note's face plus its side insets (`70ch`), centred in whatever pane it is in; a task file's is 24rem, as wide as its properties widget. **A note is set at 16px**, the plain editor, mail composer and `DiffView` at 14px: a note is long-form reading, and at 14px in a 48rem column a line ran to some 110 characters, past the 60–75 that long reading wants. H1 is 1.5em, so 24px, the same `text-2xl` as Home's and Settings' titles. **A heading belongs to what follows it**: it has air above (padding, 0.4–0.6em by level) and none below, and a list straight under it drops its own air above, so the gap above a heading is always the larger. Padding rather than margin, and the same whether the `#` shows, so nothing jumps.

## Rules

- Advance `base` before the write lands. Content comparison, not path/mtime or pausing the watcher, is what stops a save echoing back as a foreign edit.
- Only normalization counts as our own write. It is idempotent; a `relink` rewrite carries real content and must merge.
- `merge3` reports an overlap, never picks a side. The report is what routes to the banner.
- A reload is never an undo step, or ⌘Z restores stale text and autosave clobbers the other writer.
- No extension rewrites what it did not see a user type. A reload carries no `userEvent`, and every filter and listener that edits the document (Holi's and the patched table package's) leaves such a transaction alone; anything else lands in the buffer, autosaves, and turns a teammate's pull into a commit of ours.
- Block decorations come from a `StateField`, never a `ViewPlugin`: CodeMirror throws in `new EditorView` and the note opens blank.
- Motion inside CodeMirror is paint only. Animating width, height, font-size or padding pegs the measure loop ([ui-system.md](../ui-system.md)).
- A slide mark is `white-space: pre`, and transitions only under `.cm-marks-sliding`, or `## ` wraps three lines tall and headings animate shut on open. That class sits on `.cm-content`: CodeMirror rewrites the editor element's `class` when focus changes, which wiped it on the click that should have slid.
- `requestMeasure()` does not move the caret layer. The slide does one `coordsAtPos` per frame, never a transaction per frame.
- A widget's `eq` compares only what it renders from; live preview rebuilds on every arrow key.
- The wiki grammar owns its range, or the parser's phantom inner link shadows the chip.
- Block widgets apply `--editor-inset` themselves.
- A widget standing in for source keeps the source's height (the comment banner, the divider). A block element inside a line gets an empty line box on either side from CodeMirror's cursor anchors, so a line's widget is inline.
- The selection bubble's buttons use `mousedown` + `preventDefault`, so the selection survives the press. The bubble is absent on read-only and locked files and outside the notes stack; Ask agent is absent with no agent service.
- A block action edits lines and nothing else: no node, no id, nothing stored beside the file. Its user event is `move.line`, which the renumbering filter reads as a reshape.
- A mark with no markdown syntax is written in the form GitHub renders (`==`, `<mark>`, `<u>`, `<div align>`), never in a syntax only Holi reads.
- A view setting (full width, small text, lock) is machine-local and never in the file.
- The block drag carries its own data type, so a drop is never read as dropped text; CodeMirror's own drop handling stays for text.
- Completion chrome is scoped by the `cm-holi-completion` class to outrank CodeMirror, holds no hex, and keeps `icons` on (the table menu styles off it).

## Rejected

- Animating the source/rendered swap (View Transitions, frozen caret, gap marks): pegs the measure loop.
- A source/rendered mode toggle: loses reveal-on-caret.
- Revealing the whole line: one typo collapsed every chip on it.
- Rendering every binary in place, or converting PDFs to markdown on entry: the agent cannot read them.
- Our own completion engine or a React overlay: Radix menus take focus the editor must keep.
- Switching the editor to Tiptap for ReUI's page editor: it would rewrite files on open and save, and lose frontmatter, wiki-links, live preview, the external-write merge and exact line numbers for the agent.
- Page toggles in frontmatter: see the page controls.
- A table header-row toggle and resizable column widths (ReUI's): GFM requires exactly one header row and stores no widths, and a table has no identity to key a local width by.
- People in `@`: a vault is a repository, not a team space, and a person has no page a link could point at.
